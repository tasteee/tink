# Zest 1.0 readiness

Status as of the audit on branch `xoxo/dreamy-keller-e1gdvm`. Scope: the
`@tasteee/zest` package and the docs site that documents it.

**Baseline.** Build, release gate, typecheck, 338 unit tests and 262 browser
tests all pass. The docs site builds and all 113 routes render with no
console errors, no unregistered `z-*` tags and no held-back elements.

## Done in this pass

- Held back the 14 text-editor elements. v1 is **97 public elements**.
- Deleted the stale per-element markdown. The docs site is the one source.
- Untracked `.env` and removed stray files from the repo root.
- Added a CI workflow (`.github/workflows/ci.yml`): build, release gate,
  typecheck, unit and browser tests on every PR. Before this, only the
  deploy ran, so nothing gated a merge.
- Fixed the README (typos, "zero dependencies", `ink.css` fonts claim).

## Gate 1: API consistency (the DX work)

- [x] **Type the enum props.** `tone`, `size`, `kind`, `color`, `direction`,
  `side`, `align` and `position` are all typed, and a test holds them to
  shared lists. `size` on `z-container` and `z-spacer` stays open on purpose:
  it takes any CSS length.
- [x] **Unify the vocabularies.** One shared list per prop name, and each
  element takes only what it renders. `tone` is
  `neutral|primary|secondary|success|warning|danger`. `size` is
  `xs|sm|md|lg|xl|xxl` (controls use `sm|md|lg`, text uses the full scale).
  `kind` is `solid|soft|outline|ghost|plain` (`z-surface` `filled` is now
  `solid`; `z-swap` and `z-theme-switcher` use `kind` for layout). Text
  `color` is `neutral|primary|secondary|success|warning|danger|muted|strong`.
- [x] **Dead props removed.** `z-label` `size` had no CSS and did nothing.
- [ ] **Docs drifted from the code** on `small|medium|large` sizes and
  `color="white"` (renamed in 0.9.0). Fixed by hand in `api-notes.json`. Add
  a check that fails when the docs values differ from the types.
- [ ] **Check `neutral` on the 3-tone controls.** `z-checkbox`, `z-input`,
  `z-select` and 10 others type `neutral`, but their docs list only
  `primary|secondary`. `z-checkbox`'s CSS styles only those two; check the rest.
- [ ] **One-value tones.** `z-sidebar`, `z-nav-menu`, `z-breadcrumbs` and a few
  more only react to `secondary`. Decide whether they should be a boolean.
- [ ] **Booleans on `z-tree`.** `selected` and `expanded` are arrays, not
  booleans. Confirm the names do not read as booleans next to the `is-*`
  rule, and rename if they do.
- [ ] **Event names.** `change` (19), `select` (13), `open`/`close`/`input`
  follow the platform. Single-use names (`imagealign`, `tablemerge`,
  `linkunlink`) were text-editor and are now held back. Re-check the rest
  for one casing and tense rule.
- [ ] **Descriptions in `custom-elements.json`.** All 754 attributes and all
  elements have none, so editor hover docs are empty. The text lives in
  `apps/blog/src/docs/api-notes.json`. Feed it into the manifest at build,
  and make the release gate fail on a missing description.

## Not in 1.0 (held back)

Resizable panels, virtual list, markdown, terminal, post meta, chart, editor
canvas, progressive blur, the chat family, and the text-editor family. The
list is `scripts/held-back.mjs`. The gate fails the build if one leaks.
