# Zest 1.0 readiness

Status as of the audit on branch `xoxo/dreamy-keller-e1gdvm`. Scope: the
`@tasteee/zest` package and the docs site that documents it.

**Baseline.** Build, release gate, typecheck, 338 unit tests and 262 browser
tests all pass. The docs site builds and all 113 routes render with no
console errors, no unregistered `z-*` tags and no held-back elements.

## Done in this pass

- Held back the 14 text-editor elements. v1 is **97 public elements**.
- Deleted the stale per-element markdown. The docs site is the one source.
- Untracked `.env` and removed stray files from the repo root.
- Added a CI workflow (`.github/workflows/ci.yml`): build, release gate,
  typecheck, unit and browser tests on every PR. Before this, only the
  deploy ran, so nothing gated a merge.
- Fixed the README (typos, "zero dependencies", `ink.css` fonts claim).

## Gate 1: API consistency (the DX work)

- [x] **Enum props are typed.** 126 closed props across the library. The
  last 16 plain `string` enums are done (`aligns-x` / `aligns-y`, `status`,
  `shape`, `underline`, `axis`, `selection`, `level`, `type`, and the rest).
  Two are open on purpose and say so with `"open": true` in their note:
  `z-container` `size` (any CSS length) and `z-status-dot` `status` (custom
  statuses with `--color`).
- [x] **Unify the vocabularies.** One shared list per prop name, and each
  element takes only what it renders. `tone` is
  `neutral|primary|secondary|success|warning|danger`. `size` is
  `xs|sm|md|lg|xl|xxl` (controls use `sm|md|lg`, text uses the full scale).
  `kind` is `solid|soft|outline|ghost|plain` (`z-surface` `filled` is now
  `solid`; `z-swap` and `z-theme-switcher` use `kind` for layout). Text
  `color` is `neutral|primary|secondary|success|warning|danger|muted|strong`.
  Breakpoints are their own vocabulary (`small|medium|large|extra-large`,
  used by `stack-below` and the per-breakpoint `columns`), so they are not
  sizes.
- [x] **Dead props removed.** `z-label` `size` had no CSS and did nothing.
- [x] **`neutral` on the 13 three-tone controls was a lie.** It was typed but
  styled nowhere, so `tone="neutral"` gave the default accent, not a neutral
  one. Removed from the type; they take `primary|secondary`.
- [x] **Docs values match the types, enforced.** The release gate fails when
  a closed type has no values in the notes, when the notes list different
  values, or when the notes list values for a plain `string` that is not
  marked `"open": true`.
- [ ] **One-value tones.** `z-sidebar`, `z-nav-menu`, `z-breadcrumbs` and a few
  more only react to `secondary`. Decide whether they should be a boolean.
- [ ] **Booleans on `z-tree`.** `selected` and `expanded` are arrays, not
  booleans. Confirm the names do not read as booleans next to the `is-*`
  rule, and rename if they do.
- [ ] **Event names.** `change` (19), `select` (13), `open`/`close`/`input`
  follow the platform. Single-use names (`imagealign`, `tablemerge`,
  `linkunlink`) were text-editor and are now held back. Re-check the rest
  for one casing and tense rule.
- [x] **Descriptions in `custom-elements.json`.** Every element, attribute
  and event has one (97, 683 and 69). The text lives in
  `packages/zest/api-notes.json`, which the docs site also reads. The release
  gate fails on a missing description, and on a note for something that no
  longer exists.

## Gate 2: tests

Done. 1,000+ tests across the unit and browser suites, a coverage floor in CI,
and a consumer test against the real tarball.

- [x] **A smoke test for every element** (`elements.smoke.test.ts`, driven by
  `custom-elements.json`). Each of the 97 upgrades and renders without an
  error, and every attribute stays in step with its property.
- [x] **Axe on every element**, at rest in the dark and the light theme, and
  on the seven elements that open, while open. Found and fixed: a `z-marquee`
  crash when a prop changed, and no accessible name on `z-alert-dialog` and on
  the `z-command` list.
- [x] **Keyboard tests for 22 more interactive elements**
  (`keyboard.long-tail.test.ts`). Found and fixed: `z-color-picker` could not
  be closed with Escape, `z-context-menu` opened from the keyboard never took
  focus so the arrow keys did nothing, and `z-sidebar` group labels failed
  contrast.
- [x] **Every string is replaceable.** 16 hardcoded English strings (`Previous
  page`, `Hue`, `Color theme`, ...) now come from `setLocale()`, and
  `locale-coverage.test.ts` fails on a new one.
- [x] **Firefox and Safari are out of scope.** `SUPPORT.md` says Chrome and
  Edge 117+ only, and that nothing else is tested or promised.
- [x] **Coverage floor in CI.** 50% statements and lines, 40% branches and
  functions, and 80/65/70/85 on the 20 core elements. Today: 55 / 44 / 47 / 55.
- [x] **Consumer smoke test** (`pnpm test:consumers`, its own CI job). Packs
  the tarball, installs it into clean plain-HTML, React + TypeScript, Vue and
  Svelte projects, builds them, and clicks a switch in Chromium.
- [x] **JSX typings ship with the package.** React users had none; the docs
  told them to hand-write one line per element. `@tasteee/zest/react` is
  generated from the manifest, and the consumer test proves `kind="huge"` is a
  compile error.

Not done, on purpose or for later:

- [ ] A generic test that every documented event fires. Events are covered
  where a keyboard test triggers them.
- [ ] Keyboard tests for `z-sortable`, `z-dropzone`, `z-dock` and `z-avatar-stack`.
- [ ] A visual regression check. Nothing compares pixels today.

## Not in 1.0 (held back)

Resizable panels, virtual list, markdown, terminal, post meta, chart, editor
canvas, progressive blur, the chat family, and the text-editor family. The
list is `scripts/held-back.mjs`. The gate fails the build if one leaks.
