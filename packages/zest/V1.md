# Zest 1.0 readiness

Status as of the audit on branch `xoxo/dreamy-keller-e1gdvm`. Scope: the
`@tasteee/zest` package and the docs site that documents it.

**Baseline.** Build, release gate, typecheck, 338 unit tests and 262 browser
tests all pass. The docs site builds and all 113 routes render with no
console errors, no unregistered `z-*` tags and no held-back elements.

## Done in this pass

- Held back the 14 text-editor elements. v1 is **97 public elements**.
- Deleted the stale per-element markdown. The docs site is the one source.
- Untracked `.env` and removed stray files from the repo root.
- Added a CI workflow (`.github/workflows/ci.yml`): build, release gate,
  typecheck, unit and browser tests on every PR. Before this, only the
  deploy ran, so nothing gated a merge.
- Fixed the README (typos, "zero dependencies", `ink.css` fonts claim).

## Gate 0: leaked secret (owner action)

Nothing in the repo uses Convex or the JWT key any more. The `.env` is gone
from the tree and ignored.

- [ ] **Revoke the old `JWT_PRIVATE_KEY` and Convex deployment keys.** They
  are still in git history (commit `511b5ee`). Treat them as public until
  revoked. Purging history means `git filter-repo` plus a force-push to
  `main`, which rewrites every commit. Do that only on purpose.

## Gate 1: API consistency (the DX work)

- [ ] **Type the enum props.** 69 props named `size`, `tone`, `kind`,
  `direction`, `color`, `placement`, `align`, `side`, `position` are still
  plain `string` across 46 elements. The 0.9.0 changelog says
  `size="huge"` is a type error. Today that is true for 9 elements only.
  Apply `oneOf(...)` from `src/shared/prop-types.ts`.
- [ ] **Unify the vocabularies.** `tone` is `neutral|primary|secondary` on
  13 elements and adds `success|warning|danger` on 3. `kind` is
  `solid|outline|ghost|soft|plain` on `z-button` and
  `filled|soft|outline|ghost|plain` on `z-surface`. Pick one set per prop
  name, or rename where the meaning differs.
- [ ] **Booleans on `z-tree`.** `selected` and `expanded` are arrays, not
  booleans. Confirm the names do not read as booleans next to the `is-*`
  rule, and rename if they do.
- [ ] **Event names.** `change` (19), `select` (13), `open`/`close`/`input`
  follow the platform. Single-use names (`imagealign`, `tablemerge`,
  `linkunlink`) were text-editor and are now held back. Re-check the rest
  for one casing and tense rule.
- [ ] **Descriptions in `custom-elements.json`.** All 754 attributes and all
  elements have none, so editor hover docs are empty. The text lives in
  `apps/blog/src/docs/api-notes.json`. Feed it into the manifest at build,
  and make the release gate fail on a missing description.

## Gate 2: tests

Today: unit tests cover the form controls, button and the shared helpers.
Browser tests cover a11y, keyboard, form participation, locale and RTL.
64 of 97 elements have no element-specific test. Manifest-driven contract
tests cover them only generically.

- [ ] One smoke test per element: renders, upgrades, reflects each prop,
  fires each documented event.
- [ ] Axe run on every element in its default and open states.
- [ ] Keyboard map test for every interactive element in the docs.
- [ ] **Firefox and WebKit** in the browser project. `SUPPORT.md` promises
  Firefox 129+ and Safari 17.5+ but only Chromium runs.
- [ ] Coverage floor in CI (`test:coverage`), set from today's number.
- [ ] **Consumer smoke test.** `npm pack`, install the tarball into clean
  plain-HTML, React 19 + TypeScript, Vue 3 and Svelte 5 projects. Check
  import, types, a rendered element and one event in each.

## Not in 1.0 (held back)

Resizable panels, virtual list, markdown, terminal, post meta, chart, editor
canvas, progressive blur, the chat family, and the text-editor family. The
list is `scripts/held-back.mjs`. The gate fails the build if one leaks.
